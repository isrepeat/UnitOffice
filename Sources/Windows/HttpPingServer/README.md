# HttpPingServer

Для просмотра дизайна открой `Web/Chat.html` в браузере. В режиме предпросмотра отображаются примерные сообщения. Для обмена сообщениями запусти сервер и открой `/local` или `/sedo`. MSBuild копирует папку `Web` рядом с исполняемым файлом. При переносе сервера скопируй её вместе с ним.

Diagnostic пишет журнал в консоль и в `%TEMP%\UnitOffice.HttpPingServer.log`. В журнал попадают запуск сервера, методы и статусы HTTP-запросов и ошибки. Пароль и текст сообщений в журнал не записываются.

Проект использует NuGet-пакеты `UniversalDevKit.Helpers` и `UniversalDevKit.Diagnostic` версии `0.1.0`. Для локальной сборки положи оба `.nupkg` в `C:\!PackagesFeed\Windows` и восстанови пакеты NuGet. Diagnostic должен быть собран той же версией MSVC, что и HttpPingServer.

## Обмен сообщениями: локальный ↔ СЕДО

Сервер запускается на локальном компьютере. На локальном открой `http://192.168.202.46:8080/local`, на СЕДО — `http://192.168.202.46:8080/sedo`. Страница сразу выбирает имя отправителя. Старый адрес `/chat` оставляет ручной выбор имени.

Запусти сервер из Visual Studio или PowerShell:

```powershell
.\x64\Debug\UnitOffice.HttpPingServer.exe 192.168.202.46
```

При запуске введи в консоли общий пароль из 16–1023 печатных ASCII-символов без пробелов. Затем введи тот же пароль на обеих страницах. Отправь сообщение с локального, проверь получение на СЕДО и отправь ответ. Состояние подключения отображается над историей. После ошибки отправки текст сохраняется для повторной отправки.

### API для следующих интеграций

- `GET /messages?after=0` — JSON вида `{"latest":1,"messages":[{"id":1,"sender":"local","text":"Привет"}]}`. Передавай последний полученный `id` в `after`, чтобы получать только новые сообщения. Опрос страницы — раз в секунду.
- `POST /messages` — текст UTF-8 в теле, заголовок `X-Chat-Sender: local` или `X-Chat-Sender: sedo`. Ответ `200` означает, что сервер сохранил сообщение.
- Оба метода требуют заголовок `X-Chat-Key` с общим кодом. Страница запоминает код в `sessionStorage` после успешного входа и использует его при обновлении вкладки. Если сервер отклоняет код при входе, страница удаляет его и просит ввести новый.
- Ошибки: `400` — неверный отправитель, курсор или текст; `401` — неверный код; `405` — неверный метод; `413` — больше 16000 байтов. Страница ограничивает ввод 4000 символами.

Сервер хранит последние 200 сообщений в памяти; после перезапуска история и счётчик очищаются. При перезапуске клиент сбрасывает курсор, если новый счётчик меньше старого. Если клиент долго отсутствовал, часть сообщений может быть потеряна. Имена отправителей выбираются пользователем; это не идентификация компьютера. Автоматическое выполнение команд, гарантированная доставка и сохранение на диск пока не реализованы. При обрыве ответа на POST сообщение могло сохраниться: повторная отправка может создать дубликат.

HTTP передаёт код и сообщения открытым текстом. Используй этот прототип для тестовых сообщений в доверенной сети; для рабочего удалённого управления потребуется защищённый транспорт и отдельная модель разрешений.

Для проверки из локальной сети выполни команды ниже **на ПК с сервером** в PowerShell от имени администратора. Здесь IPv4 сервера — `192.168.202.46`, подсеть — `192.168.202.0/24`, активный профиль брандмауэра — `Public`. Если настройки сети отличаются, подставь свои значения и укажи тот же IP при запуске сервера.

## Право на регистрацию URL

`HTTP.sys` проверяет, может ли учётная запись зарегистрировать этот URL. Резервирование позволяет запускать сервер из Visual Studio с обычными правами.

```powershell
netsh http add urlacl url=http://192.168.202.46:8080/ "user=$(whoami)" listen=yes
```

Если PowerShell запущен под другой учётной записью, подставь в `user=` имя пользователя, под которым работает Visual Studio.

## Входящие подключения

Добавь одно правило, разрешающее входящий TCP на порт `8080` только из указанной подсети в профиле `Public`.

```powershell
New-NetFirewallRule -Name "HttpPingServer-LAN-8080" `
  -DisplayName "HttpPingServer LAN TCP 8080" `
  -Direction Inbound -Action Allow -Protocol TCP -LocalPort 8080 `
  -LocalAddress 192.168.202.46 -RemoteAddress 192.168.202.0/24 `
  -Profile Public
```

## Проверка

Запусти `UnitOffice.HttpPingServer` в конфигурации `Debug | x64` и убедись, что в консоли появился адрес `http://192.168.202.46:8080/`. Сначала открой `http://192.168.202.46:8080/test` на ПК с сервером, затем на втором ПК. На странице ожидаются строки `PASS`, а в консоли сервера — `GET /test -> 200` и `POST /ping -> 200`.

## Удаление настроек

Из PowerShell от имени администратора:

```powershell
Remove-NetFirewallRule -Name "HttpPingServer-LAN-8080"
netsh http delete urlacl url=http://192.168.202.46:8080/
```

Если ранее добавлялось правило с тем же отображаемым именем без параметра `-Name`, у него будет другое внутреннее имя. Найди его через `Get-NetFirewallRule -DisplayName "HttpPingServer LAN TCP 8080"`.
