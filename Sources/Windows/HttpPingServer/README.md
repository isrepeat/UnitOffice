# HttpPingServer

Чат между локальным компьютером и компьютером СЕДО. Сервер работает на локальном ПК, оба клиента подключаются браузером. Страница `/sedo` принадлежит этому чату и не является самим приложением СЕДО.

## Сборка и файлы запуска

Проект использует NuGet-пакеты `UniversalDevKit.Helpers` и `UniversalDevKit.Diagnostic` версии `0.1.0`. Для локальной сборки положи оба `.nupkg` в `C:\!PackagesFeed\Windows` и восстанови пакеты NuGet. Diagnostic должен быть собран той же версией MSVC, что и HttpPingServer.

Собери `UnitOffice.HttpPingServer` в Visual Studio, конфигурация `Debug | x64`. Исполняемый файл находится в `!artifacts/projects/Windows/msbuild/UnitOffice.HttpPingServer/bin/x64/Debug`. Рядом с exe должны находиться DLL зависимостей и папка `Web`. При переносе сервера переноси этот комплект целиком. Скрипты настройки `SetupHttps.ps1` и `TrustHttps.ps1` хранятся в `Sources/Windows/HttpPingServer` и запускаются отдельно из исходников.

При каждой сборке, включая сборку без изменений C++, MSBuild копирует всё содержимое `Web` с заменой в `$(TargetDir)Web`, сохраняя подпапки. Быстрый пропуск сборки Visual Studio отключён для этого проекта. Сервер читает ресурсы рядом со своим exe, запрещает кеширование ответов и добавляет к URL CSS/JS версию по содержимому. После обновления ресурсов достаточно обновить вкладку; после замены exe сервер нужно перезапустить. Для просмотра дизайна без сервера открой `Web/Chat.html`.

## Первичная настройка HTTPS на локальном ПК

Настройка выполняется один раз для выбранного IP и учётной записи запуска сервера. Нужны права администратора Windows. Обычный запуск сервера и Visual Studio после настройки не требуют повышения прав.

Текущие параметры:

| Параметр | Значение |
| --- | --- |
| IP локального сервера | `192.168.202.46` |
| HTTPS | TCP `8443` |
| Разрешённая подсеть клиентов | `192.168.202.0/24` |
| Локальный клиент | `https://192.168.202.46:8443/local` |
| Клиент на СЕДО | `https://192.168.202.46:8443/sedo` |

Открой Windows PowerShell **от имени администратора** и выполни:

```powershell
cd C:\WORK\Windows\Projects\UnitOffice\Sources\Windows\HttpPingServer
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\SetupHttps.ps1 -ServerUser "$env:USERDOMAIN\$env:USERNAME"
```

Если настройку выполняешь под другой учётной записью администратора, передай в `-ServerUser` именно учётную запись, под которой запускаются сервер и Visual Studio, например `DESKTOP-T0JJ5C1\isrepeat`.

Скрипт выполняет четыре независимых действия:

1. Создаёт самоподписанный сертификат с IP в SAN, назначением Server Authentication и сроком действия 12 месяцев. Закрытый ключ хранится в `LocalMachine\My` и не экспортируется.
2. Устанавливает публичный сертификат в доверенные корневые сертификаты локального ПК и привязывает его к `192.168.202.46:8443` в HTTP.sys.
3. Резервирует URL `https://192.168.202.46:8443/` для указанного пользователя.
4. Добавляет правило брандмауэра `UnitOffice.HttpPingServer-HTTPS-8443`: входящий TCP 8443 на IP сервера только из указанной подсети, во всех профилях сети.

Скрипт выводит путь к публичному `.cer` и SHA256 файла. По умолчанию файл находится в `%USERPROFILE%\Downloads\UnitOffice.HttpPingServer\UnitOffice.HttpPingServer.cer`. Локально отдельно импортировать сертификат не нужно.

Для другого IP или подсети используй параметры `-Address` и `-RemoteSubnet`; каталог экспорта задаётся через `-CertificateDirectory`. Такой же IP необходимо передать exe при запуске. Повторный запуск использует подходящий существующий сертификат; чужая TLS-привязка не заменяется. Если сертификат истёк или сменился IP, потребуется новая привязка и повторное доверие на клиентах. Существующие URL ACL и правило брандмауэра автоматически не перенастраиваются для другого пользователя или сети — проверь их отдельно.

## Доверие сертификату на компьютере СЕДО

Передай на СЕДО публичный `UnitOffice.HttpPingServer.cer`. Закрытый ключ переносить не нужно. Проверь, что сертификат получен с нашего локального ПК; для проверки SHA256 используй значение из его консоли.

### Без командной строки и PowerShell

1. Открой `.cer` двойным щелчком.
2. Нажми **«Установить сертификат» → «Текущий пользователь»**.
3. Выбери **«Поместить все сертификаты в следующее хранилище» → «Обзор» → «Доверенные корневые центры сертификации»**.
4. Заверши мастер и подтверди установку сертификата.
5. Заново открой HTTPS-чат в браузере.

Доверие применяется к текущему пользователю Windows. Для другого пользователя импорт повторяется в его сессии. Если политика компьютера запрещает установку сертификата, обратись к администратору СЕДО. Простое продолжение просмотра после предупреждения сертификата не заменяет настройку доверия для Clipboard API.

### Если PowerShell доступен

Передай также `TrustHttps.ps1` и выполни, подставив SHA256 из консоли локального ПК:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\TrustHttps.ps1 -CertificateFile .\UnitOffice.HttpPingServer.cer -ExpectedSha256 ВСТАВЬ_SHA256
```

Скрипт проверяет SHA256 и добавляет сертификат в `CurrentUser\Root`. Windows может запросить подтверждение установки.

## Обычный запуск и проверка

После первичной настройки запусти сервер кнопкой F5 в Visual Studio или из папки сборки:

```powershell
.\UnitOffice.HttpPingServer.exe
```

Без аргументов в Debug и Release используется `https://192.168.202.46:8443/`. Аргумент `--https` необязателен. Для другого IP:

```powershell
.\UnitOffice.HttpPingServer.exe 192.168.202.46
```

В Debug пароль по умолчанию — `unitoffice-local-test-2026`, консоль его не запрашивает. В Release пароль вводится при запуске: 16–1023 печатных ASCII-символов без пробелов. Debug-пароль является общим тестовым кодом, а не индивидуальной идентификацией пользователей.

Ожидаемая строка журнала: `Listening on https://192.168.202.46:8443/`.

В поле сообщения Enter отправляет текст и прикреплённое изображение. Shift+Enter или Alt+Enter добавляет перенос строки. Кнопка «Отправить» также доступна; пустое сообщение без изображения не отправляется.

На локальном ПК открой `https://192.168.202.46:8443/local`, на СЕДО — `https://192.168.202.46:8443/sedo`. Введи пароль на обеих страницах. Имя отправителя выбирается адресом страницы; `/chat` оставляет ручной выбор. При переходе с HTTP на HTTPS войди заново: это разные хранилища сессии браузера.

Проверь:

- Страницы открываются без предупреждения сертификата и показывают «Подключено».
- Текстовые сообщения приходят в обе стороны.
- Win+Shift+S → выделение области → Ctrl+V в поле чата даёт предпросмотр PNG.
- Иконка копирования под полученной картинкой показывает «Изображение скопировано», после чего PNG вставляется через Ctrl+V.
- На странице `https://192.168.202.46:8443/test` проверки завершаются строками `PASS`.

Если доступна консоль браузера, `window.isSecureContext` должно возвращать `true`, а `typeof navigator.clipboard?.write` — `function`. Копирование выполняется по нажатию иконки; браузер должен разрешать доступ к буферу.

## Диагностика доступа

Diagnostic пишет журнал в консоль и `%TEMP%\UnitOffice.HttpPingServer.log`. Пароль и содержимое сообщений в журнал не записываются.

| Симптом | Что проверить |
| --- | --- |
| `HttpAddUrl (Win32 error 5): Access is denied` | Резервирование HTTPS URL для пользователя, запускающего exe. Привязка сертификата сама по себе это право не даёт. |
| Браузер сообщает «Отказано в подключении» | Сервер запущен; в журнале именно HTTPS и порт 8443, а не HTTP 8080. |
| Локально открывается, на СЕДО нет | IP сервера, связность сети, правило TCP 8443 и попадание IP клиента в разрешённую подсеть. |
| Предупреждение сертификата | Доверие установлено для текущего пользователя, IP в URL совпадает с SAN, сертификат не истёк. |
| Копирование недоступно | Страница открыта по доверенному HTTPS, браузер разрешает Clipboard API. Запасной вариант: правая кнопка на самой картинке → «Копировать изображение». |
| Нет новых иконок или старый дизайн | Обновлён `Web` именно рядом с работающим exe; обнови вкладку, при необходимости Ctrl+F5. |
| `HTTP 401` | Пароль страницы совпадает с паролем запущенного сервера. |

Проверка системных настроек в PowerShell:

```powershell
netsh http show sslcert ipport=192.168.202.46:8443
netsh http show urlacl url=https://192.168.202.46:8443/
Get-NetFirewallRule -Name UnitOffice.HttpPingServer-HTTPS-8443
```

В выводе `show urlacl` должен присутствовать сам HTTPS URL и пользователь. Пустой список не означает успех настройки: код возврата `netsh` при отсутствии записи может быть нулевым.

Если URL отсутствует, выполни **от администратора**:

```powershell
netsh http add urlacl url=https://192.168.202.46:8443/ "user=$env:USERDOMAIN\$env:USERNAME" listen=yes
```

Если сервер запускается другой учётной записью, подставь её в `user=`. После исправления снова запусти exe или F5.

## Скриншоты и ограничения истории

Для отправки скриншота нажми Win+Shift+S, выдели область и вставь Ctrl+V в поле сообщения. Можно добавить подпись или убрать вложение. Поддерживается один PNG до 4 МиБ на сообщение. При ошибке отправки текст и изображение остаются для повторной попытки.

Под изображением расположены иконки копирования PNG и скачивания. Скачивание использует обычную папку загрузок или диалог браузера; подпапку страница не назначает.

Перетащи файлы в область ввода сообщения или вставь их через Ctrl+V, если браузер передаёт файлы из буфера обмена. Можно отправить до 200 файлов общим размером до 10 МиБ с подписью или без неё. Один вставленный PNG до 4 МиБ отображается как скриншот. У файлов есть иконка скачивания, а у текстовых файлов также есть иконка копирования содержимого.

История ограничена 200 сообщениями и 32 МиБ суммарного текста и вложений в Base64; при превышении удаляются самые старые сообщения. Данные хранятся только в памяти. Перезапуск очищает историю и счётчик; клиент сбрасывает курсор при обнаружении нового меньшего счётчика. Если клиент долго отсутствовал, часть сообщений может быть потеряна.

Автоматическое выполнение команд, гарантированная доставка и сохранение на диск не реализованы. При обрыве ответа на POST сообщение могло сохраниться: повторная отправка может создать дубликат. Имена отправителей выбираются клиентом и не идентифицируют компьютер.

## API

- `GET /messages?after=0` возвращает JSON вида `{"latest":1,"messages":[{"id":1,"sender":"local","text":"Привет","image":""}]}`. Передавай последний полученный `id` в `after`. Страница опрашивает сервер раз в секунду.
- `POST /messages` принимает текст UTF-8. Заголовок `X-Chat-Sender`: `local` или `sedo`. Ответ `200` означает, что сообщение сохранено в памяти.
- Для PNG добавляется `X-Chat-Type: image`. Тело: PNG data URL в Base64, перевод строки LF и подпись UTF-8 до 16000 байтов (может быть пустой). Поле `image` в истории содержит data URL.
- Для одного файла добавляется `X-Chat-Type: file`. Тело: имя, закодированное через `encodeURIComponent`, LF, содержимое в Base64, LF и подпись UTF-8 до 16000 байтов (может быть пустой). Для нескольких файлов используется `X-Chat-Type: files`: подряд идут пары строк имени и содержимого, затем пустая строка и подпись. История возвращает вложения в массиве `files` с полями `name` и `data`.
- Оба метода требуют `X-Chat-Key`. Страница запоминает пароль в `sessionStorage` после успешного входа; при отклонении пароля на входе удаляет его.
- Ошибки: `400` — неверный отправитель, курсор, текст или формат изображения; `401` — неверный пароль; `405` — неверный метод; `413` — превышен размер тела (16000 байтов для текста, 5610000 байтов с изображением). Страница ограничивает текст 4000 символами.
- `POST /ping` возвращает `pong`, `GET /test` открывает диагностику.

## Диагностика из вкладки настоящего СЕДО

Сниппет находится в `Snippets/SedoDiagnostics.js`. На компьютере СЕДО сначала проверь открытие нашего HTTPS-чата без предупреждения сертификата. Затем открой именно настоящее приложение СЕДО, DevTools → Sources → Snippets → New snippet, вставь содержимое файла и запусти Ctrl+Enter. Выбери контекст нужного фрейма, если приложение расположено в iframe.

Сниппет выводит origin страницы, отправляет один `POST https://192.168.202.46:8443/ping` с фиксированной тестовой строкой без cookies, пароля чата и Referer, показывает доступные записи Resource Timing и наблюдает новые запросы 5 минут. Выполни обычные действия в СЕДО: открой список и карточку документа. `sedoProbe.report()` выводит таблицу и возвращает отчёт; `sedoProbe.ping()` повторяет тест; `sedoProbe.stop()` останавливает наблюдение. Повторный запуск останавливает прежний экземпляр. Перезагрузка страницы прекращает наблюдение.

Отчёт содержит тип инициатора, origin, путь, имена query-параметров без значений, число запросов и доступный браузеру статус. Числовые сегменты пути и UUID заменяются на `:id`; прочие сегменты могут содержать сведения о документах, поэтому проверь таблицу перед передачей. Тела, заголовки авторизации, cookies и ответы API не читаются; отчёт не отправляется на локальный сервер. Сниппет не изменяет fetch/XHR сайта и не перебирает адреса API.

Это кандидаты на API, а не полный каталог. Методы запросов, WebSocket, запросы других фреймов/воркеров и записи, уже удалённые из буфера браузера, могут отсутствовать; `unknown` в статусе не означает ошибку. Для уточнения открой Network → Fetch/XHR с Preserve log и выполни те же действия. Не передавай необработанный HAR: он может содержать токены и документы.

`confirmed` означает прочитанный ответ `200 pong`. Ответ на `POST /ping` содержит `Access-Control-Allow-Origin: *`, поэтому сниппет может прочитать его с любого origin без учётных данных. Этот запрос не требует CORS preflight. Для API чата CORS не включён. При `unconfirmed` проверь Network и Console: запрос всё ещё могут блокировать CSP `connect-src`, ограничения доступа к локальной сети или недоверенный сертификат. Сопоставь время теста с журналом сервера.

## Необязательный HTTP на 8080

HTTP включается явно: `UnitOffice.HttpPingServer.exe --http`. Он передаёт пароль и сообщения открытым текстом, а копирование PNG через Clipboard API по сетевому IP недоступно. Для обычной работы используй HTTPS.

При необходимости настрой HTTP на сервере из PowerShell **от администратора**:

```powershell
netsh http add urlacl url=http://192.168.202.46:8080/ "user=$env:USERDOMAIN\$env:USERNAME" listen=yes
New-NetFirewallRule -Name "HttpPingServer-LAN-8080" -DisplayName "HttpPingServer LAN TCP 8080" -Direction Inbound -Action Allow -Protocol TCP -LocalPort 8080 -LocalAddress 192.168.202.46 -RemoteAddress 192.168.202.0/24 -Profile Public
```

## Удаление сетевых настроек

После остановки сервера, из PowerShell **от администратора**:

```powershell
Remove-NetFirewallRule -Name "UnitOffice.HttpPingServer-HTTPS-8443"
netsh http delete urlacl url=https://192.168.202.46:8443/
netsh http delete sslcert ipport=192.168.202.46:8443
```

Если настраивался HTTP, отдельно удали `HttpPingServer-LAN-8080` и URL ACL `http://192.168.202.46:8080/`. Эти команды не удаляют сертификаты: при полном отключении чата удали только его сертификат по проверенному отпечатку из личного и доверенного хранилищ сервера и из доверенного хранилища каждого клиента.
